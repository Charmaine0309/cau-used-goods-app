# 用户管理阶段开发说明

本文档已按当前后端实际代码核对，核对范围包括 `backend/internal/user`、`backend/internal/middleware`、`backend/internal/auth` 中账号恢复调用链，以及 `backend/cmd/server/main.go` 的路由注册。

接口调用细节已拆分到 `backend/docs/sxy/用户管理/接口文档/`。本文保留模块边界、状态规则、实现现状和联调注意事项。

## 1. 当前实现范围

用户管理模块当前分为用户端接口和后台管理接口。

用户端接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/users/me` | 查看当前登录用户资料 |
| `GET` | `/users/me/restriction` | 查看当前账号限制原因 |
| `GET` | `/users/:id/public` | 查看其他用户公开资料 |
| `PUT` | `/users/profile` | 修改个人资料 |
| `POST` | `/users/avatar` | 上传并更新头像 |
| `POST` | `/users/student-verify` | 提交学生认证 |
| `GET` | `/users/student-verify` | 查看本人学生认证状态 |
| `POST` | `/users/cancel` | 主动注销账号 |

后台接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/admin/users` | 用户列表、搜索、筛选、分页 |
| `GET` | `/admin/users/student-verifications` | 学生认证列表 |
| `GET` | `/admin/users/:id` | 用户聚合详情 |

| `PUT` | `/admin/users/:id/status` | 修改账号状态 |

| `GET` | `/admin/users/:id/orders` | 用户订单记录 |

| `GET` | `/admin/users/:id/logs` | 用户管理操作日志 |

服务入口没有全局 `/api` 前缀。

## 2. 模块边界

用户管理模块负责：

- 用户基础档案查询与修改。
- 学生认证提交与后台审核。
- 账号状态生命周期管理。
- 角色管理。
- 主动注销与重新激活的用户侧状态变更。
- 用户关联商品、订单、举报、申诉、评价、后台日志的聚合查询。
- 账号状态变化时协调商品、订单、消息和后台日志模块。

用户管理模块不负责：

- 微信登录 openid 换取，该逻辑在 `auth` 模块。
- 商品、订单、举报、申诉本身的业务判定。
- 直接处理举报或申诉结论，只接受 `relatedType/relatedId` 作为处置依据。

## 3. 用户状态模型

当前用户状态由三个字段共同表达：

| 字段 | 说明 |
| --- | --- |
| `auth_status` | 学生认证状态：`UNVERIFIED` / `PENDING` / `VERIFIED` / `REJECTED` |
| `account_status` | 账号状态：`NORMAL` / `DISABLED` / `BANNED` / `CANCELED` |
| `is_deleted` | 普通业务查询过滤标记；注销账号为 `1` |

`account_status` 与 `is_deleted` 的当前约定：

| account_status | is_deleted |
| --- | ---: |
| `NORMAL` | 0 |
| `DISABLED` | 0 |
| `BANNED` | 0 |
| `CANCELED` | 1 |

学生认证状态流转：

```text
UNVERIFIED -> PENDING
REJECTED   -> PENDING
PENDING    -> VERIFIED
PENDING    -> REJECTED
```

账号状态流转：

```text
NORMAL   -> DISABLED
NORMAL   -> BANNED
NORMAL   -> CANCELED
DISABLED -> NORMAL
DISABLED -> BANNED
BANNED   -> NORMAL
CANCELED -> NORMAL
```

其中 `BANNED -> NORMAL` 只能由 `SUPER_ADMIN` 执行，且必须关联已通过的申诉。

## 4. 权限与中间件

路由注册位于 `backend/internal/user/router.go`。

用户端接口组 `/users` 使用：

```text
Auth + ReadableAccount
```

其中写操作额外使用或在 handler/service 中校验 `NormalAccount`：

- `PUT /users/profile`
- `POST /users/avatar`
- `POST /users/student-verify`
- `POST /users/cancel`

后台接口组 `/admin/users` 使用：

```text
Auth + Admin
```

`PUT /admin/users/:id/role` 额外使用：

```text
SuperAdmin
```

`Auth` 会校验 JWT 和 `token_version`。`Admin` / `SuperAdmin` 会实时查询数据库，要求管理员账号仍为 `account_status=NORMAL` 且未删除。

## 5. 字段校验规则

| 字段 | 规则 |
| --- | --- |
| `nickname` | trim 后 1-50 字符 |
| `avatarUrl` | trim 后 1-255 字符；允许 http(s) URL 或 `/uploads/avatar/` 路径 |
| `phone` | 必须匹配 `^1[3-9]\d{9}$` |
| `studentId` | 6-30 位字母或数字，且不能被其他用户使用 |
| `realName` | trim 后 2-30 字符 |
| `college` | trim 后 1-50 字符 |
| `description` | 审核说明不超过 500 字符；驳回时必填 |
| `reason` | 后台状态/角色变更原因必填，不超过 500 字符 |
| `relatedType` | 只能为 `REPORT` 或 `APPEAL`，且必须和 `relatedId` 同时传或同时不传 |

## 7. 账号生命周期副作用

后台将账号改为 `DISABLED` 或 `BANNED` 时：

- 如果存在 `WAIT_MEET` 订单，操作失败，要求先处理待面交订单。
- 如果存在 `PENDING_CONFIRM` 订单，会在同一事务内自动异常关闭。
- 自动下架该用户所有 `ON_SALE` 商品。
- 写入用户状态变更日志，相关商品下架也写入后台日志。
- 事务提交后发送系统消息；消息发送失败不回滚主业务。

用户主动注销时：

- 只允许 `role=USER` 的正常账号注销。
- 必须 `confirm=true`。
- 存在 `PENDING_CONFIRM` 或 `WAIT_MEET` 订单时不允许注销。
- 自动下架在售商品。
- 设置 `account_status=CANCELED`、`is_deleted=1`，并递增 `token_version`。

重新激活由登录认证模块 `/auth/reactivate` 触发，最终调用用户管理模块：

- 设置 `account_status=NORMAL`、`is_deleted=0`。
- 角色强制恢复为 `USER`。
- 递增 `token_version`。
- 不自动恢复商品上架状态。

## 9. 联调注意事项

- 前端路径不要添加 `/api` 前缀。
- 所有 `/users` 和 `/admin/users` 接口都需要 `Authorization: Bearer <token>`。
- `DISABLED`、`BANNED` 账号可以进入部分只读接口，但不能执行写操作。
- `CANCELED` 账号无法继续使用旧 token，重新登录会进入恢复流程。
- 普通管理员看不到 `openid`，也看不到日志完整 IP；超级管理员可见。
- 用户列表默认排除 `CANCELED`，需要查注销账号时显式传 `accountStatus=CANCELED`。
- 商品和评价关联记录支持 `dataScope=ACTIVE|DELETED|ALL`，默认 `ACTIVE`。

## 10. 建议测试用例

| 用例 | 预期 |
| --- | --- |
| 无 token 调用 `/users/me` | 401 |
| NORMAL 用户修改昵称 | 返回更新后的 user |
| DISABLED 用户修改资料 | 403 |
| 上传超过 2MB 头像 | 400 |
| 提交重复学号 | 409 |
| PENDING 状态重复提交认证 | 409 |
| 管理员审核非 PENDING 用户 | 409 |
| 普通用户访问 `/admin/users` | 403 |
| ADMIN 修改其他 ADMIN 状态 | 403 |
| SUPER_ADMIN 修改角色为 `ADMIN` | 成功并写入日志 |
| 用户存在待面交订单时封禁 | 409/400 业务错误，状态不变 |
| 普通用户主动注销后旧 token 访问接口 | 401 或 403，取决于中间件阶段 |
