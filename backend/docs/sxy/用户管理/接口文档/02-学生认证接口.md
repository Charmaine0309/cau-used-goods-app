# 学生认证接口

## 1. 提交学生认证

```http
POST /users/student-verify
Authorization: Bearer <token>
Content-Type: application/json
```

该接口要求当前账号为 `NORMAL`。

### 请求参数

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `studentId` | string | 是 | trim 后 6-30 位字母或数字，且不能被其他用户使用 |
| `realName` | string | 是 | trim 后 2-30 字符 |
| `college` | string | 是 | trim 后 1-50 字符 |

请求示例：

```json
{
  "studentId": "20240001",
  "realName": "张三",
  "college": "信息与电气工程学院"
}
```

### 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "userId": 1,
    "studentId": "20240001",
    "realName": "张三",
    "college": "信息与电气工程学院",
    "authStatus": "PENDING",
    "accountStatus": "NORMAL"
  },
  "timestamp": "2026-06-09 12:00:00"
}
```

### 状态规则

```text
UNVERIFIED -> PENDING
REJECTED   -> PENDING
PENDING    -> 不允许重复提交
VERIFIED   -> 不允许重复提交
```

## 2. 查看本人学生认证

```http
GET /users/student-verify
Authorization: Bearer <token>
```

### 响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "userId": 1,
    "studentId": "20240001",
    "realName": "张三",
    "college": "信息与电气工程学院",
    "authStatus": "PENDING",
    "accountStatus": "NORMAL"
  },
  "timestamp": "2026-06-09 12:00:00"
}
```

前端可根据 `authStatus` 展示：

| authStatus | 展示建议 |
| --- | --- |
| `UNVERIFIED` | 显示认证入口 |
| `PENDING` | 显示审核中，不允许重复提交 |
| `VERIFIED` | 显示已认证 |
| `REJECTED` | 显示失败原因入口，并允许重新提交 |

当前接口不返回驳回说明；如需展示驳回说明，需要结合后台日志或后续扩展字段。

## 3. 管理员查询学生认证列表

```http
GET /admin/users/student-verifications?authStatus=PENDING
Authorization: Bearer <admin_token>
```

需要 `ADMIN` 或 `SUPER_ADMIN`。

### 查询参数

| 参数 | 类型 | 必填 | 默认 | 规则 |
| --- | --- | --- | --- | --- |
| `authStatus` | string | 否 | `PENDING` | `UNVERIFIED` / `PENDING` / `VERIFIED` / `REJECTED` |

### 响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [
      {
        "userId": 1,
        "studentId": "20240001",
        "realName": "张三",
        "college": "信息与电气工程学院",
        "authStatus": "PENDING",
        "accountStatus": "NORMAL"
      }
    ]
  },
  "timestamp": "2026-06-09 12:00:00"
}
```

说明：当前实现该列表不分页，按 `users.update_time DESC` 排序。

## 4. 管理员审核学生认证

```http
PUT /admin/users/{id}/student-verify
Authorization: Bearer <admin_token>
Content-Type: application/json
```

需要 `ADMIN` 或 `SUPER_ADMIN`。

### 路径参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | number | 是 | 待审核用户 ID，必须大于 0 |

### 请求参数

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `authStatus` | string | 是 | 只能为 `VERIFIED` 或 `REJECTED` |
| `description` | string | 否 | 不超过 500 字符；驳回时必填 |

通过示例：

```json
{
  "authStatus": "VERIFIED",
  "description": "学生认证审核通过"
}
```

驳回示例：

```json
{
  "authStatus": "REJECTED",
  "description": "学号与姓名不匹配"
}
```

### 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "userId": 1,
    "studentId": "20240001",
    "realName": "张三",
    "college": "信息与电气工程学院",
    "authStatus": "VERIFIED",
    "accountStatus": "NORMAL"
  },
  "timestamp": "2026-06-09 12:00:00"
}
```

### 审核规则

- 管理员不能审核自己的认证。
- 目标用户必须存在、未删除、账号为 `NORMAL`。
- 目标用户当前必须为 `authStatus=PENDING`。
- `authStatus=REJECTED` 时 `description` 必填。
- `authStatus=VERIFIED` 且 `description` 为空时，后端会写入默认通过说明。
- 审核操作会写入 `admin_logs`，操作类型为 `STUDENT_VERIFY_APPROVE` 或 `STUDENT_VERIFY_REJECT`。

## 5. 常见错误

| 场景 | HTTP | code |
| --- | ---: | ---: |
| 未登录 | 401 | 401 |
| 普通用户访问后台认证接口 | 403 | 403 |
| 学号格式错误 | 400 | 400 |
| 学号已被使用 | 409 | 409 |
| 正在审核中重复提交 | 409 | 409 |
| 已认证用户重复提交 | 409 | 409 |
| 审核目标不存在 | 404 | 404 |
| 管理员审核自己 | 403 | 403 |
| 目标账号状态异常 | 403 | 403 |
| 目标认证状态不是 PENDING | 409 | 409 |
| 驳回但未填写说明 | 400 | 400 |
| 审核说明超过 500 字符 | 400 | 400 |
