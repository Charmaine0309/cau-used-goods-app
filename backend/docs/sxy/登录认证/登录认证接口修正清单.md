# 登录认证接口修正清单

本文档记录登录认证、用户资料、学生认证和管理员认证审核接口的修正约定。目标是补齐输入约束、账号状态限制、管理员实时权限校验和前端可用的业务错误提示。

## 1. 总体约定

- 字段限制以数据库字段长度为底线，以业务合理性为接口校验标准。
- 数据库继续保留唯一约束、字段长度、外键等底线保护。
- 后端接口负责在写入数据库前完成格式、长度、枚举、状态流转校验。
- 前端不解析数据库原始错误；后端需要返回明确的业务提示信息。
- JWT 保留，用于识别当前用户身份；关键权限和账号状态仍以数据库实时状态为准。
- 远程头像转存当前阶段暂时保留，安全风险后续正式部署前再处理。

## 2. `/auth/dev-login` 文档修正

开发登录接口只用于开发环境快速生成 token，不负责维护昵称。

原文档中的 `nickname` 字段删除。

修正后的请求体：

```json
{
  "openid": "dev_user_openid_001",
  "role": "USER"
}
```

管理员测试：

```json
{
  "openid": "admin_openid_001",
  "role": "ADMIN"
}
```

说明：

- `server.env=dev` 时注册 `/auth/dev-login`。
- `server.env=prod` 时不注册该接口。
- 昵称、头像、手机号统一通过 `PUT /users/profile` 或 `POST /users/avatar` 维护。

## 3. 字段输入限制

后端 service 层增加字段校验。校验规则不应和数据库冲突，也不做过度限制。

| 字段 | 数据库字段 | 后端接口限制 | 说明 |
| --- | --- | --- | --- |
| `openid` | `VARCHAR(64)` | 1-64 字符 | 仅开发登录或微信登录内部使用 |
| `code` | 不入库 | 1-128 字符 | 微信登录 code |
| `role` | `VARCHAR(20)` | 仅允许 `USER` / `ADMIN` | dev-login 使用 |
| `nickname` | `VARCHAR(50)` | 1-50 字符 | 去除首尾空格 |
| `phone` | `VARCHAR(20)` | 必须符合手机号格式 | 见第 4 节 |
| `avatarUrl` | `VARCHAR(255)` | 1-255 字符 | 允许 `http/https` 或 `/uploads/avatar/` |
| `studentId` | `VARCHAR(30)` | 6-30 字符，建议数字/字母 | 学号 |
| `realName` | `VARCHAR(30)` | 2-30 字符 | 学生真实姓名 |
| `college` | `VARCHAR(100)` | 1-50 字符 | 数据库留 100，业务限制 50 |
| `description` | `VARCHAR(500)` 或日志描述字段 | 0-500 字符 | 驳回认证时必填 |

## 4. 手机号格式校验

`phone` 必须校验手机号格式，不只校验长度。

建议初版采用中国大陆手机号格式：

```text
^1[3-9]\d{9}$
```

规则：

- 允许不传 `phone`，表示不修改手机号。
- 如果传入 `phone`，必须符合手机号格式。
- 不允许空字符串覆盖已有手机号。

错误提示建议：

```json
{
  "code": 400,
  "message": "手机号格式不正确",
  "data": null
}
```

## 5. 账号状态限制

以下写操作需要校验当前用户：

```text
account_status = NORMAL
is_deleted = 0
```

涉及接口：

```text
PUT  /users/profile
POST /users/avatar
POST /users/student-verify
```

如果账号状态异常，返回明确业务提示：

```json
{
  "code": 403,
  "message": "当前账号状态不可操作",
  "data": null
}
```

## 6. 学生认证提交规则

学生认证接口：

```text
POST /users/student-verify
```

状态流转调整为：

```text
UNVERIFIED -> PENDING
REJECTED   -> PENDING
PENDING    -> 不允许重复提交
VERIFIED   -> 不允许重复提交
```

提交前校验：

- 当前用户必须存在且 `is_deleted=0`。
- 当前用户 `account_status=NORMAL`。
- `studentId` 符合长度和格式要求。
- `realName` 符合长度要求。
- `college` 符合长度要求。
- `studentId` 未被其他用户使用。

建议业务提示：

| 场景 | code | message |
| --- | --- | --- |
| 学号格式错误 | 400 | 学号格式不正确 |
| 姓名长度错误 | 400 | 真实姓名长度应为 2-30 个字符 |
| 学院长度错误 | 400 | 学院名称长度应为 1-50 个字符 |
| 学号已被使用 | 409 | 学号已被使用 |
| 正在审核中 | 409 | 学生认证正在审核中，请勿重复提交 |
| 已认证 | 409 | 学生认证已通过，不能重复提交 |
| 账号状态异常 | 403 | 当前账号状态不可操作 |

## 7. 学生认证审核边界

管理员审核接口：

```text
PUT /admin/users/:id/student-verify
```

需要补充以下规则：

- 管理员必须通过实时数据库校验，不能只信 JWT 中的 `role`。
- 目标用户必须存在。
- 目标用户 `is_deleted=0`。
- 目标用户 `account_status=NORMAL`。
- 目标用户 `auth_status=PENDING`。
- 管理员不能审核自己的认证。
- `authStatus` 只允许 `VERIFIED` / `REJECTED`。
- `description` 长度不超过 500。
- `authStatus=REJECTED` 时，`description` 必填。
- 审核操作必须写入 `admin_logs`。

建议业务提示：

| 场景 | code | message |
| --- | --- | --- |
| 非管理员访问 | 403 | 管理员权限 required |
| 管理员账号异常 | 403 | 当前管理员账号状态不可操作 |
| 目标用户不存在 | 404 | 用户不存在 |
| 目标账号异常 | 403 | 目标用户账号状态不可审核 |
| 审核自己 | 403 | 管理员不能审核自己的认证 |
| 非 PENDING 状态 | 409 | 认证状态已变化，请刷新后重试 |
| 驳回未填写说明 | 400 | 驳回时必须填写审核说明 |
| 审核说明过长 | 400 | 审核说明不能超过 500 个字符 |

## 8. 管理员实时权限校验

当前 `Admin()` 中间件只读取 JWT 中的 `role=ADMIN`。后续改为可复用的实时数据库校验。

推荐实现方向：

```go
func Admin(db *sql.DB) gin.HandlerFunc
```

校验逻辑：

```sql
SELECT role, account_status
FROM users
WHERE id = ? AND is_deleted = 0
LIMIT 1
```

通过条件：

```text
role = ADMIN
account_status = NORMAL
```

分层约定：

- `Auth`：解析 JWT，确认当前请求是谁发起的。
- `Admin`：查询数据库，确认当前用户现在仍然是正常管理员。
- `Service`：确认该管理员能否操作具体目标对象。

这是后端权限控制的通用做法，后续所有 `/admin/*` 接口可复用。

## 9. JWT 使用约定

JWT 不删除，也不视为累赘。

JWT 负责：

- 识别当前用户身份。
- 提供 `userId`。
- 提供基础 `role` 信息。
- 减少每个接口重新登录或重新解析身份的成本。

JWT 不负责：

- 最终确认账号是否仍可用。
- 最终确认管理员权限是否仍有效。
- 最终确认学生认证状态是否仍有效。

当前阶段不实现：

- token 黑名单。
- token version。
- 强制登出。

当前阶段需要实现：

- 管理员接口实时查数据库确认管理员状态。
- 用户写操作实时查数据库确认账号状态。
- 交易类接口使用 `Verified` 中间件确认学生认证和账号状态。

## 10. 业务错误提示约定

前端不解析数据库原始错误。

后端需要把常见数据库错误和业务冲突映射成稳定业务提示。

错误返回格式仍保持：

```json
{
  "code": 409,
  "message": "学号已被使用",
  "data": null,
  "timestamp": "2026-05-31 00:00:00"
}
```

前端处理方式：

- 根据 `code` 做通用分流。
- 直接展示后端返回的 `message`。
- 不解析 `Duplicate entry`、SQL 错误文本或数据库 key 名。

建议映射：

| 场景 | code | message |
| --- | --- | --- |
| 参数格式错误 | 400 | 对应字段的业务提示 |
| 未登录或 token 无效 | 401 | 登录已失效，请重新登录 |
| 普通用户访问管理员接口 | 403 | 管理员权限 required |
| 账号状态异常 | 403 | 当前账号状态不可操作 |
| 资源不存在 | 404 | 用户不存在 |
| 学号唯一约束冲突 | 409 | 学号已被使用 |
| 认证状态冲突 | 409 | 认证状态已变化，请刷新后重试 |
| 数据库内部错误 | 500 | 服务器异常，请稍后重试 |

开发阶段可以保留部分原始错误用于调试，但联调稳定后应逐步收敛为业务提示。

## 11. 远程头像转存约定

当前阶段保留远程头像转存能力。

原因：

- 方便微信头像地址落库。
- 便于前端调试个人资料修改。

后续正式部署前需要补充：

- 头像 URL 域名白名单。
- 重定向目标限制。
- 真实图片内容校验。
- 更严格的下载超时和大小限制。

## 12. 测试用例清单

后续接口测试至少覆盖以下用例。

| 用例 | 前置条件 | 请求 | 预期结果 |
| --- | --- | --- | --- |
| dev-login 普通用户 | `server.env=dev` | `POST /auth/dev-login` role=USER | 返回 USER token |
| dev-login 管理员 | `server.env=dev` | `POST /auth/dev-login` role=ADMIN | 返回 ADMIN token |
| dev-login 非法 role | `server.env=dev` | role=ROOT | 返回 400 |
| wechat-login 缺少 code | 无 | `POST /auth/wechat-login` 空请求 | 返回 400 |
| 无 token 查自己 | 无 | `GET /users/me` | 返回 401 |
| 错误 token 查自己 | token 非法 | `GET /users/me` | 返回 401 |
| 普通用户访问管理员接口 | USER token | `GET /admin/users/student-verifications` | 返回 403 |
| 修改昵称成功 | NORMAL 用户 | `PUT /users/profile` | 返回更新后的 user |
| 手机号格式错误 | NORMAL 用户 | `PUT /users/profile` phone=123 | 返回 400 |
| 禁用用户修改资料 | DISABLED 用户 | `PUT /users/profile` | 返回 403 |
| 上传超大头像 | NORMAL 用户 | `POST /users/avatar` 大于 2MB | 返回 400 |
| 上传非图片头像 | NORMAL 用户 | `POST /users/avatar` txt 文件 | 返回 400 |
| 提交学生认证成功 | UNVERIFIED 用户 | `POST /users/student-verify` | 状态变为 PENDING |
| 学号格式错误 | NORMAL 用户 | studentId 非法 | 返回 400 |
| 学号重复 | 已存在相同 studentId | `POST /users/student-verify` | 返回 409 |
| PENDING 重复提交 | 用户已 PENDING | `POST /users/student-verify` | 返回 409 |
| VERIFIED 重复提交 | 用户已 VERIFIED | `POST /users/student-verify` | 返回 409 |
| 管理员审核通过 | ADMIN，目标 PENDING | `PUT /admin/users/:id/student-verify` VERIFIED | 状态变为 VERIFIED，写入日志 |
| 管理员审核驳回 | ADMIN，目标 PENDING | REJECTED + description | 状态变为 REJECTED，写入日志 |
| 驳回无说明 | ADMIN，目标 PENDING | REJECTED 但 description 空 | 返回 400 |
| 审核非 PENDING 用户 | ADMIN，目标非 PENDING | 审核请求 | 返回 409 |
| 管理员审核自己 | ADMIN 审核自己 userId | 审核请求 | 返回 403 |
