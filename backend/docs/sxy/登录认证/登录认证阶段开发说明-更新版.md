# 登录认证阶段开发说明（更新版）

本文档已按当前后端实际代码核对，核对范围包括 `backend/cmd/server/main.go`、`backend/internal/auth`、`backend/internal/middleware`、`backend/pkg/jwt`、`backend/pkg/response` 以及账号恢复依赖的 `backend/internal/user` 生命周期逻辑。

接口调用细节已从本文拆分到 `接口文档` 目录，本文只保留模块实现说明、状态规则和前后端联调注意事项。

## 1. 当前实现范围

登录认证模块当前提供 3 个接口：

| 方法 | 路径 | 说明 | 注册条件 |
| --- | --- | --- | --- |
| `POST` | `/auth/wechat-login` | 微信小程序登录 | 始终注册 |
| `POST` | `/auth/dev-login` | 开发环境模拟登录 | 仅 `server.env=dev` 注册 |
| `POST` | `/auth/reactivate` | 注销账号重新激活 | 始终注册 |

服务入口没有全局 `/api` 前缀，默认监听端口来自 `config/config.yaml` 的 `server.port`，示例配置为 `8080`。因此本地默认 Base URL 为：

```text
http://127.0.0.1:8080
```

## 2. 关键文件核对

| 文件 | 当前职责 |
| --- | --- |
| `backend/internal/auth/router.go` | 注册 `/auth` 路由。`/auth/dev-login` 只在 `server.env=dev` 时注册。 |
| `backend/internal/auth/handler.go` | 绑定 JSON 请求体，调用认证服务，按统一响应格式返回结果。 |
| `backend/internal/auth/service.go` | 处理微信 code 换 openid、开发登录、JWT 签发、注销账号恢复凭证签发与恢复确认。 |
| `backend/internal/auth/repository.go` | 按 openid 查询或创建用户，更新登录时间，开发环境下调整角色。 |
| `backend/pkg/jwt/token.go` | 生成和解析 JWT，支持 `ACCESS` 与 `REACTIVATE` 两种 token 类型。 |
| `backend/internal/middleware/auth.go` | 校验 `Authorization: Bearer <token>`，校验 token version，写入 `userID` 和 `role`。 |
| `backend/pkg/response/response.go` | 统一响应体：`code`、`message`、`data`、`timestamp`。 |

## 3. 登录与账号状态规则

新用户首次登录时由后端自动创建 `users` 记录：

```text
role = USER
auth_status = UNVERIFIED
account_status = NORMAL
is_deleted = 0
token_version = 0
```

普通登录成功返回 `ACCESS` JWT，前端后续调用受保护接口时传：

```http
Authorization: Bearer <token>
```

当同一 openid 对应的账号为 `CANCELED` 或 `is_deleted=1` 时，登录接口不会签发正常业务 token，而是返回 `requiresReactivation=true` 和短期 `reactivationToken`。前端需要引导用户确认恢复账号后调用 `/auth/reactivate`。

账号重新激活成功后：

```text
account_status = NORMAL
is_deleted = 0
role = USER
token_version = token_version + 1
```

## 4. JWT 设计

`ACCESS` token 包含：

```json
{
  "userId": 1,
  "role": "USER",
  "tokenType": "ACCESS",
  "tokenVersion": 0,
  "exp": 1234567890,
  "iat": 1234560000
}
```

`REACTIVATE` token 用于注销账号恢复确认，有效期为 5 分钟，不允许访问业务接口。

`ACCESS` token 默认有效期来自 `jwt.expire_hours`，配置小于等于 0 时使用 168 小时。

认证中间件除了解析 JWT，还会实时读取数据库中的 `token_version`。账号注销或重新激活会递增 `token_version`，旧 token 会失效。

## 5. 统一响应格式

所有成功响应 HTTP 状态码为 `200`：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-06-09 12:00:00"
}
```

错误响应沿用同一结构：

```json
{
  "code": 400,
  "message": "错误原因",
  "data": null,
  "timestamp": "2026-06-09 12:00:00"
}
```

常用错误码：

| code | HTTP | 说明 |
| --- | ---: | --- |
| `400` | 400 | 请求体缺失、字段格式错误、枚举值非法 |
| `401` | 401 | 未登录、token 缺失、token 无效或过期 |
| `403` | 403 | token 类型不允许访问业务接口、账号状态或权限不允许 |
| `409` | 409 | 业务状态冲突，例如恢复凭证无效、未确认恢复 |
| `500` | 500 | 服务端内部错误或第三方接口异常 |

## 7. 配置说明

配置模板位于 `backend/config/config.yaml.example`：

```yaml
server:
  env: dev
  port: 8080

jwt:
  secret: change_this_to_a_long_random_secret
  expire_hours: 168

wechat:
  app_id: your_wechat_mini_program_app_id
  app_secret: your_wechat_mini_program_app_secret
```

注意：

- `server.env=dev` 时注册 `/auth/dev-login`。
- 非 dev 环境不注册 `/auth/dev-login`。
- 微信登录依赖真实 `wechat.app_id` 和 `wechat.app_secret`。
- `jwt.secret` 必须替换为足够长的随机字符串。

## 8. 前端联调重点

- 所有接口路径均为根路径直挂，例如 `/auth/wechat-login`，不是 `/api/auth/wechat-login`。
- 登录成功后保存 `data.token`，后续受保护接口统一传 `Authorization: Bearer <token>`。
- 发现 `requiresReactivation=true` 时，不要把 `reactivationToken` 当业务 token 使用。
- `reactivationToken` 只能传给 `/auth/reactivate`，且有效期 5 分钟。
- `message` 为后端可展示错误信息，前端可直接用于 toast 或弹窗，但要对 `401` 做统一重新登录处理。

## 9. 建议测试用例

| 用例 | 预期 |
| --- | --- |
| dev 环境调用 `/auth/dev-login` 且不传 openid | 使用 `dev_openid_001` 登录成功 |
| dev 环境传 `role=ADMIN` | 返回 ADMIN token，用户角色更新为 ADMIN |
| dev 环境传非法 role | 返回 400 |
| 微信登录缺少 code | 返回 400 |
| 微信配置为空时调用微信登录 | 返回 500 |
| 注销账号再次微信登录 | 返回 `requiresReactivation=true` 和 `reactivationToken` |
| `confirm=false` 调用 `/auth/reactivate` | 返回 409 |
| 恢复凭证过期或类型错误 | 返回 409 |
| 恢复成功后用旧 token 访问业务接口 | 返回 401 |
