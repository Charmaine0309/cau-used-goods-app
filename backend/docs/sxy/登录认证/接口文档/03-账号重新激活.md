# 账号重新激活接口

## 1. 接口信息

```http
POST /auth/reactivate
Content-Type: application/json
```

用于恢复已主动注销的账号。前置条件是 `/auth/wechat-login` 或 `/auth/dev-login` 返回：

```json
{
  "requiresReactivation": true,
  "reactivationToken": "..."
}
```

## 2. 请求参数

| 字段 | 类型 | 必填 | 规则 | 说明 |
| --- | --- | --- | --- | --- |
| `reactivationToken` | string | 是 | trim 后不能为空 | 登录接口返回的恢复凭证 |
| `confirm` | boolean | 是 | 必须为 `true` | 用户二次确认恢复账号 |

请求示例：

```json
{
  "reactivationToken": "jwt_reactivation_token",
  "confirm": true
}
```

## 3. 成功响应

恢复成功后返回新的业务 token：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "new_jwt_access_token",
    "user": {
      "id": 1,
      "nickname": "张三",
      "avatarUrl": "/uploads/avatar/a.png",
      "role": "USER",
      "authStatus": "VERIFIED",
      "accountStatus": "NORMAL"
    }
  },
  "timestamp": "2026-06-09 12:00:00"
}
```

前端应保存 `data.token` 并替换旧登录态。

## 4. 恢复后的账号变化

后端会调用用户管理模块执行恢复：

```text
account_status = NORMAL
is_deleted = 0
role = USER
token_version = token_version + 1
```

说明：

- 保留原 `user_id`。
- 保留原学生认证状态。
- 不自动重新上架历史商品。
- 注销前或注销期间的旧业务 token 会因 `token_version` 变化而失效。

## 5. 错误响应

| 场景 | HTTP | code | 说明 |
| --- | ---: | ---: | --- |
| 请求体格式错误 | 400 | 400 | JSON 不合法或缺少必填字段 |
| `confirm=false` | 409 | 409 | 必须确认重新激活账号 |
| `reactivationToken` 为空 | 409 | 409 | 恢复凭证不能为空 |
| token 无效、过期或不是 `REACTIVATE` 类型 | 409 | 409 | 恢复凭证无效或已过期 |
| 账号状态不是已注销 | 409 | 409 | 当前账号状态不可重新激活 |
| 恢复服务不可用 | 409 | 409 | 用户管理恢复服务未注入 |

错误示例：

```json
{
  "code": 409,
  "message": "恢复凭证无效或已过期",
  "data": null,
  "timestamp": "2026-06-09 12:00:00"
}
```
