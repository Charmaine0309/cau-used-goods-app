# 登录认证接口通用约定

## 1. Base URL

后端当前没有全局 `/api` 前缀。本地默认地址：

```text
http://127.0.0.1:8080
```

接口路径示例：

```text
POST http://127.0.0.1:8080/auth/wechat-login
```

## 2. 统一响应

成功：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-06-09 12:00:00"
}
```

失败：

```json
{
  "code": 400,
  "message": "错误原因",
  "data": null,
  "timestamp": "2026-06-09 12:00:00"
}
```

前端判断时建议优先使用 HTTP 状态码和响应体 `code`。成功固定为 `code=0`。

## 3. 鉴权头

登录认证接口本身不需要 `Authorization`。登录成功后，其他受保护接口需要：

```http
Authorization: Bearer <token>
```

注意：`reactivationToken` 不是业务访问 token，只能用于 `/auth/reactivate`。

## 4. 登录返回用户对象

登录成功时 `data.user` 来自 `auth.User`，字段为：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | 用户 ID |
| `nickname` | string/null | 昵称 |
| `avatarUrl` | string/null | 头像地址 |
| `role` | string | `USER` / `ADMIN` / `SUPER_ADMIN` |
| `authStatus` | string | `UNVERIFIED` / `PENDING` / `VERIFIED` / `REJECTED` |
| `accountStatus` | string | `NORMAL` / `DISABLED` / `BANNED` / `CANCELED` |
| `lastLoginTime` | string/null | 最近登录时间，存在时返回 |

`openid`、`isDeleted`、`tokenVersion` 不会返回给前端。

## 5. 常用错误码

| HTTP | code | 典型场景 |
| ---: | ---: | --- |
| 400 | 400 | 请求体格式错误、必填字段缺失、字段长度超限、枚举值非法 |
| 401 | 401 | 业务接口 token 缺失、无效、过期或已失效 |
| 403 | 403 | token 类型错误，或账号/权限不允许访问 |
| 409 | 409 | 账号恢复未确认、恢复凭证无效或状态冲突 |
| 500 | 500 | 微信接口异常、数据库异常或服务端内部错误 |
