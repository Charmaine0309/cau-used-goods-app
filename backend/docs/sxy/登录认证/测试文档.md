# 登录认证接口测试文档

## 1. 测试目标

验证登录认证、用户资料、头像上传、学生认证和管理员认证审核相关接口是否符合补丁版设计说明。

本次测试重点覆盖：

- 请求字段限制是否生效。
- token 缺失、错误、权限不足时是否返回明确业务提示。
- 账号状态异常时是否限制业务操作。
- 学生认证状态流转是否符合 `UNVERIFIED -> PENDING -> VERIFIED/REJECTED` 规则。
- 管理员审核是否校验管理员实时角色、账号状态和目标用户状态。

## 4. 测试数据说明

脚本只创建和修改 `api_test_` 前缀的测试账号，例如：

```text
api_test_user_时间戳
api_test_admin_时间戳
api_test_verify_时间戳
```

脚本不会主动修改普通业务账号。

数据库状态预置用于覆盖以下场景：

- 管理员被降权后，旧 token 不能继续访问后台。
- 管理员账号被禁用后，旧 token 不能继续访问后台。
- 普通用户账号被禁用后，不能修改资料或上传头像。
- 学生认证状态分别处于 `UNVERIFIED`、`PENDING`、`VERIFIED`、`REJECTED` 时的边界行为。

## 5. 覆盖接口

本次脚本覆盖以下接口：

| 模块 | 接口 | 覆盖点 |
| --- | --- | --- |
| 登录认证 | `POST /auth/dev-login` | 普通用户、管理员、非法 role、openid 过长 |
| 微信登录 | `POST /auth/wechat-login` | 缺少 code、code 过长 |
| 用户信息 | `GET /users/me` | 缺少 token、错误 token |
| 用户资料 | `PUT /users/profile` | 修改成功、昵称为空、手机号格式错误、禁用账号 |
| 头像上传 | `POST /users/avatar` | 超大文件、非图片、禁用账号 |
| 学生认证 | `POST /users/student-verify` | 提交成功、学号格式错误、学号重复、重复提交、驳回后重新提交 |
| 管理员审核 | `GET /admin/users/student-verifications` | 普通用户访问、管理员降权、管理员禁用 |
| 管理员审核 | `PUT /admin/users/:id/student-verify` | 审核通过、审核驳回、驳回无说明、说明过长、审核非 PENDING、审核自己 |

## 7. 注意事项

- 如果只想测试不依赖数据库状态修改的基础接口，可加 `-SkipDbMutations`。
- 如果 VS Code 或 PowerShell 已经打开，修改系统 PATH 后可能不会立即生效，需要重新打开终端或显式传入 `-MysqlExe`。
- 如果后端端口不是 8080，使用 `-BaseUrl` 指定实际地址。
- 测试脚本会留下 `api_test_` 前缀测试账号，后续可按需清理。
