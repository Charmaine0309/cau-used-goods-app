# 登录认证阶段开发说明（更新版）

本文档是 `backend/docs/sxy/登录认证/登录认证阶段开发说明.md` 的更新版，已同步覆盖 `backend/docs/sxy/补丁/登录认证接口修正清单.md` 中确认的修正规则，并与当前代码改动保持一致。

## 1. 当前完成范围

本阶段已完成后端基础启动、数据库连接、统一响应、JWT、认证中间件、管理员权限中间件、`auth` 登录认证模块和 `user` 用户/学生认证模块。

当前已实现能力：

- 微信登录 `/auth/wechat-login`。
- 开发环境登录 `/auth/dev-login`。
- 当前用户信息查询 `/users/me`。
- 用户资料修改 `/users/profile`。
- 用户头像上传 `/users/avatar`。
- 学生认证提交 `/users/student-verify`。
- 学生认证状态查询 `/users/student-verify`。
- 管理员查询学生认证列表 `/admin/users/student-verifications`。
- 管理员审核学生认证 `/admin/users/:id/student-verify`。

本次补丁已增加：

- 登录和资料接口字段长度/格式校验。
- 手机号格式校验。
- 用户写操作账号状态限制。
- 学生认证提交状态流转限制。
- 学号唯一性预检查和数据库唯一冲突业务提示。
- 管理员实时数据库权限校验。
- 学生认证审核边界限制。
- 更明确的业务错误提示。

```yaml

  secret: change_this_to_a_long_random_secret
  expire_hours: 168

  app_id: your_wechat_mini_program_app_id
```

注意：

- `server.env=dev` 时注册 `/auth/dev-login`。

- `config.yaml` 包含敏感信息，不应提交。

## 4. 统一响应与错误码

统一响应格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-05-31 00:00:00",
  "requestId": "optional-request-id"
}
```

错误码约定：

| code | 含义 | 常见场景 |
| --- | --- | --- |
| `0` | 成功 | 请求处理成功 |
| `400` | 请求参数错误 | 字段格式错误、长度错误、请求体错误 |
| `401` | 未登录或 token 无效 | 缺少 token、token 过期、token 非法 |
| `403` | 无权限或状态不允许 | 普通用户访问后台、账号状态异常、管理员账号异常 |
| `404` | 资源不存在 | 用户不存在 |
| `409` | 业务冲突 | 学号重复、认证状态冲突、重复提交认证 |
| `500` | 服务端内部错误 | 数据库异常、微信接口异常等 |

前端处理约定：

- 前端根据 `code` 做通用分流。
- 前端直接展示后端返回的 `message`。
- 前端不解析数据库原始错误、SQL 错误文本或数据库 key 名。

后端当前已将常见业务冲突返回为明确业务提示，例如：

```json
{
  "code": 409,
  "message": "学号已被使用",
  "data": null,
  "timestamp": "2026-05-31 00:00:00"
}
```

## 5. 字段校验规则

字段限制以数据库字段长度为底线，以业务合理性为接口校验标准。

| 字段 | 数据库字段 | 后端接口限制 | 说明 |
| --- | --- | --- | --- |
| `openid` | `VARCHAR(64)` | 1-64 字符 | 空值时 dev-login 使用默认 openid |
| `code` | 不入库 | 1-128 字符 | 微信登录 code |
| `role` | `VARCHAR(20)` | 仅允许 `USER` / `ADMIN` | dev-login 使用 |
| `nickname` | `VARCHAR(50)` | 1-50 字符 | 去除首尾空格 |
| `phone` | `VARCHAR(20)` | 必须符合手机号格式 | 见手机号规则 |
| `avatarUrl` | `VARCHAR(255)` | 1-255 字符 | 允许 `http/https` 或 `/uploads/avatar/` |
| `studentId` | `VARCHAR(30)` | 6-30 字符，数字/字母 | 学号 |
| `realName` | `VARCHAR(30)` | 2-30 字符 | 学生真实姓名 |
| `college` | `VARCHAR(100)` | 1-50 字符 | 数据库留 100，业务限制 50 |
| `description` | 日志描述字段 | 0-500 字符 | 驳回认证时必填 |

手机号格式：

```text
^1[3-9]\d{9}$
```

说明：

- `phone` 不传表示不修改。
- `phone` 一旦传入，必须符合手机号格式。
- 不允许用空字符串覆盖已有手机号。

## 6. 接口设计

### 6.1 微信登录

```http
POST /auth/wechat-login
Content-Type: application/json
```

请求体：

```json
{
  "code": "wx_login_code"
}
```

校验：

- `code` 去除首尾空格。
- `code` 必填。
- `code` 长度不超过 128 字符。

处理流程：

```text
小程序 wx.login 获取 code
-> 前端提交 code
-> 后端调用微信 code2session
-> 获取 openid
-> 查询或创建 users 记录
-> 更新 last_login_time
-> 生成 JWT
```

新用户默认状态：

```text
role = USER
auth_status = UNVERIFIED
account_status = NORMAL
```

响应数据：

```json
{
  "token": "jwt_token",
  "user": {
    "id": 1,
    "nickname": null,
    "avatarUrl": null,
    "role": "USER",
    "authStatus": "UNVERIFIED",
    "accountStatus": "NORMAL"
  }
}
```

### 6.2 开发登录

仅 `server.env=dev` 时注册该接口。

```http
POST /auth/dev-login
Content-Type: application/json
```

普通用户测试：

```json
{
  "openid": "dev_user_openid_001",
  "role": "USER"
}
```

管理员测试：

```json
{
  "openid": "admin_openid_001",
  "role": "ADMIN"
}
```

说明：

- 本接口不接收 `nickname` 字段。
- `openid` 为空时使用默认值 `dev_openid_001`。
- `openid` 长度不超过 64 字符。
- `role` 仅允许 `USER` / `ADMIN`。
- 昵称、头像、手机号通过 `PUT /users/profile` 或 `POST /users/avatar` 修改。

### 6.3 用户详情

```http
GET /users/me
Authorization: Bearer <token>
```

响应数据包含：

```json
{
  "id": 1,
  "nickname": "张三",
  "avatarUrl": null,
  "studentId": "20240001",
  "realName": "张三",
  "college": "信息与电气工程学院",
  "phone": "13800000000",
  "role": "USER",
  "authStatus": "PENDING",
  "accountStatus": "NORMAL"
}
```

### 6.4 修改用户资料

```http
PUT /users/profile
Authorization: Bearer <token>
Content-Type: application/json
```

请求体：

```json
{
  "nickname": "张三",
  "avatarUrl": "https://example.com/avatar.png",
  "phone": "13800000000"
}
```

规则：

- 三个字段均可选，但至少传一个。
- 写操作前校验当前用户 `account_status=NORMAL` 且 `is_deleted=0`。
- `nickname`：1-50 字符。
- `phone`：必须符合手机号格式。
- `avatarUrl`：1-255 字符，允许 `http/https` 或 `/uploads/avatar/`。
- 学号、真实姓名、学院不在此接口修改，应通过学生认证接口提交。

头像转存说明：

- `avatarUrl` 可以传微信头像外链。
- 后端会下载并转存到 `backend/uploads/avatar/`。
- 最终写入数据库的是 `/uploads/avatar/文件名`。
- 当前阶段保留该能力，正式部署前再补充域名白名单、重定向限制和真实图片内容校验。

### 6.5 上传/修改用户头像

```http
POST /users/avatar
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

表单字段：

```text
avatar: 选择的图片文件
```

规则：

- 写操作前校验当前用户 `account_status=NORMAL` 且 `is_deleted=0`。
- 文件大小不超过 2MB。
- 支持 `.jpg`、`.jpeg`、`.png`、`.webp`。
- 文件保存到 `backend/uploads/avatar/`。
- 上传成功后自动写入 `users.avatar_url`。

响应数据：

```json
{
  "avatarUrl": "/uploads/avatar/abc123.png",
  "user": {
    "id": 1,
    "nickname": "张三",
    "avatarUrl": "/uploads/avatar/abc123.png",
    "studentId": null,
    "realName": null,
    "college": null,
    "phone": "13800000000",
    "role": "USER",
    "authStatus": "UNVERIFIED",
    "accountStatus": "NORMAL"
  }
}
```

### 6.6 提交学生认证

```http
POST /users/student-verify
Authorization: Bearer <token>
Content-Type: application/json
```

请求体：

```json
{
  "studentId": "20240001",
  "realName": "张三",
  "college": "信息与电气工程学院"
}
```

状态流转：

```text
UNVERIFIED -> PENDING
REJECTED   -> PENDING
PENDING    -> 不允许重复提交
VERIFIED   -> 不允许重复提交
```

提交前校验：

- 当前用户存在且 `is_deleted=0`。
- 当前用户 `account_status=NORMAL`。
- `studentId` 符合 6-30 位数字/字母。
- `studentId` 未被其他用户使用。
- `realName` 长度 2-30 字符。
- `college` 长度 1-50 字符。

常见错误：

| 场景 | code | message |
| --- | --- | --- |
| 学号格式错误 | 400 | 学号格式不正确 |
| 姓名长度错误 | 400 | 真实姓名长度应为 2-30 个字符 |
| 学院长度错误 | 400 | 学院名称长度应为 1-50 个字符 |
| 学号已被使用 | 409 | 学号已被使用 |
| 正在审核中 | 409 | 学生认证正在审核中，请勿重复提交 |
| 已认证 | 409 | 学生认证已通过，不能重复提交 |
| 账号状态异常 | 403 | 当前账号状态不可操作 |

### 6.7 查询学生认证状态

```http
GET /users/student-verify
```

响应数据：

```json
{
  "studentId": "20240001",
  "realName": "张三",
  "college": "信息与电气工程学院",
  "authStatus": "PENDING",
```

### 6.8 查询学生认证审核列表

管理员接口，需要通过 `Auth` 和实时 `Admin` 中间件。

```http
GET /admin/users/student-verifications?authStatus=PENDING
Authorization: Bearer <admin_token>
```

规则：

- `authStatus` 可选，默认 `PENDING`。
- 支持查询 `PENDING`、`VERIFIED`、`REJECTED`、`UNVERIFIED`。
- 当前管理员必须在数据库中仍满足 `role=ADMIN`、`account_status=NORMAL`、`is_deleted=0`。

响应数据：

```json
{
  "items": [
    {
      "userId": 1,
      "studentId": "20240001",
      "realName": "张三",
      "college": "信息与电气工程学院",
      "authStatus": "PENDING",
      "accountStatus": "NORMAL"
    }
  ]
}
```

### 6.9 审核学生认证

管理员接口，需要通过 `Auth` 和实时 `Admin` 中间件。

```http
PUT /admin/users/{id}/student-verify
Authorization: Bearer <admin_token>
Content-Type: application/json
```

审核通过：

```json
{
  "authStatus": "VERIFIED",
  "description": "学生认证审核通过"
}
```

审核驳回：

```json
{
  "authStatus": "REJECTED",
  "description": "学号或姓名信息不匹配"
}
```

状态流转：

```text
PENDING -> VERIFIED
PENDING -> REJECTED
```

审核规则：

- 管理员必须通过实时数据库校验。
- 目标用户必须存在。
- 目标用户 `is_deleted=0`。
- 目标用户 `account_status=NORMAL`。
- 目标用户 `auth_status=PENDING`。
- 管理员不能审核自己的认证。
- `authStatus` 只允许 `VERIFIED` / `REJECTED`。
- `description` 长度不超过 500。
- `authStatus=REJECTED` 时，`description` 必填。
- `authStatus=VERIFIED` 且 `description` 为空时，默认写入“学生认证审核通过”。
- 审核操作写入 `admin_logs`。

常见错误：

| 场景 | code | message |
| --- | --- | --- |
| 非管理员访问 | 403 | admin permission required |
| 管理员账号异常 | 403 | 当前管理员账号状态不可操作 |
| 目标用户不存在 | 404 | 用户不存在 |
| 目标账号异常 | 403 | 目标用户账号状态不可审核 |
| 审核自己 | 403 | 管理员不能审核自己的认证 |
| 非 PENDING 状态 | 409 | 认证状态已变化，请刷新后重试 |
| 驳回未填写说明 | 400 | 驳回时必须填写审核说明 |
| 审核说明过长 | 400 | 审核说明不能超过 500 个字符 |

## 7. 中间件设计

### 7.1 `Auth`

文件：`backend/internal/middleware/auth.go`

职责：

- 读取请求头 `Authorization`。
- 校验格式是否为 `Bearer <token>`。
- 解析 JWT。
- 将 `userID` 和 `role` 写入 Gin Context。

### 7.2 `Verified`

文件：`backend/internal/middleware/verified.go`

职责：

- 根据当前 `userID` 查询 `users` 表。
- 校验用户是否满足：

```text
auth_status = VERIFIED
account_status = NORMAL
is_deleted = 0
```

适用接口：

- 发布商品。
- 提交预约。
- 收藏。
- 评价。
- 举报。
- 其他要求学生认证后才能使用的交易功能。

### 7.3 `Admin`

文件：`backend/internal/middleware/admin.go`

当前实现已改为实时数据库校验：

```go
func Admin(db *sql.DB) gin.HandlerFunc
```

校验逻辑：

```sql
SELECT role, account_status
FROM users
WHERE id = ? AND is_deleted = 0
LIMIT 1
```

通过条件：

```text
role = ADMIN
account_status = NORMAL
```

分层约定：

- `Auth`：识别当前请求是谁发起的。
- `Admin`：确认当前用户现在仍然是正常管理员。
- `Service`：确认该管理员能否操作具体目标对象。

## 8. JWT 设计

文件：`backend/pkg/jwt/token.go`

JWT 中只放最小必要信息：

```json
{
  "userId": 1,
  "role": "USER",
  "exp": 1234567890,
  "iat": 1234560000
}
```

JWT 负责：

- 识别当前用户身份。
- 提供 `userId`。
- 提供基础 `role` 信息。
- 减少每个接口重新登录或重新解析身份的成本。

JWT 不负责：

- 最终确认账号是否仍可用。
- 最终确认管理员权限是否仍有效。
- 最终确认学生认证状态是否仍有效。

当前阶段不实现：

- token 黑名单。
- token version。
- 强制登出。

当前阶段已采用：

- 管理员接口实时查数据库确认管理员状态。
- 用户写操作实时查数据库确认账号状态。
- 交易类接口使用 `Verified` 中间件确认学生认证和账号状态。

| 管理员账号异常访问后台 | ADMIN 但 account_status 非 NORMAL | 管理员接口 | 返回 403 |

| 昵称为空 | NORMAL 用户 | `PUT /users/profile` nickname 为空 | 返回 400 |
| 手机号格式错误 | NORMAL 用户 | `PUT /users/profile` phone=123 | 返回 400 |
