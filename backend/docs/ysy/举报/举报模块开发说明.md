# 举报模块开发说明

## 1. 模块概述

举报模块负责处理用户对商品、用户、订单的举报功能，包括提交举报、查看举报状态、关闭举报、管理员处理举报等。

## 2. 开发思路

### 2.1 举报状态流转

```
PENDING（待处理）
    ├── 管理员标记 → PROCESSING（处理中）
    ├── 举报人关闭 → CLOSED（已关闭）
    └── 管理员处理 → APPROVED（举报成立）/ REJECTED（已驳回）
```

### 2.2 处理边界

- 举报处理接口（`/admin/reports/:id/handle`）只负责将举报处理为 `APPROVED` 或 `REJECTED`
- 不再联动修改用户、商品或订单状态
- 举报成立后的后续操作由对应模块完成：
  - 封禁用户：`PUT /admin/users/:id/status`
  - 下架商品：`PUT /admin/products/:id/status`
  - 异常关闭订单：`POST /admin/orders/:id/exception-close`
- 基于举报进行处置时，可传 `relatedType=REPORT` 和 `relatedId` 关联来源

### 2.3 废弃字段处理

- `accountStatus` 字段已废弃，如果传入会返回错误提示
- 引导管理员使用专门的用户状态接口

## 3. 接口清单

### 用户端

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/reports` | 提交举报 | 登录+认证 |
| GET | `/reports/my` | 我的举报列表 | 登录+认证 |
| GET | `/reports/:id` | 举报详情 | 登录+认证 |
| POST | `/reports/:id/close` | 关闭举报 | 登录+认证 |

### 管理员端

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/admin/reports` | 举报列表（管理员） | 登录+管理员 |
| POST | `/admin/reports/:id/processing` | 标记处理中 | 登录+管理员 |
| POST | `/admin/reports/:id/handle` | 处理举报 | 登录+管理员 |

## 4. 测试情况

- 提交举报、查看列表测试通过
- 管理员标记处理中、处理举报测试通过
- 废弃字段校验测试通过

## 5. 注意事项

- 同一用户对同一目标只能有一个待处理的举报
- 举报人只能查看自己的举报详情
- 管理员处理时需记录处理日志
