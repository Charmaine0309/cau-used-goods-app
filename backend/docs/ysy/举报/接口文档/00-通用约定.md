# 举报模块通用约定

## 1. Base URL

```text
http://127.0.0.1:8080
```

## 2. 鉴权

- 用户端接口需要登录 + 学生认证 `VERIFIED`
- 管理员端接口需要登录 + `role=ADMIN` 或 `SUPER_ADMIN`

```http
Authorization: Bearer <token>
```

## 3. 统一响应

成功：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-06-09 12:00:00"
}
```

失败：

```json
{
  "code": 400,
  "message": "错误说明",
  "data": null,
  "timestamp": "2026-06-09 12:00:00"
}
```

## 4. 分页约定

列表类接口使用：

| 参数 | 类型 | 默认 | 规则 |
| --- | --- | --- | --- |
| `page` | number | 1 | 小于 1 时按 1 处理 |
| `pageSize` | number | 20 | 小于 1 时按 20，最大 100 |

分页响应：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

## 5. 枚举

举报目标类型：

```text
PRODUCT / USER / ORDER
```

举报状态：

```text
PENDING / PROCESSING / APPROVED / REJECTED / CLOSED
```

## 6. 模块职责

举报模块负责处理用户对商品、用户、订单的举报功能，包括提交举报、查看举报状态、关闭举报、管理员处理举报等。

## 7. 关联数据表

- `reports` — 举报主表
- `report_images` — 举报凭证图片表

## 8. 核心规则

1. 举报类型：`PRODUCT`（商品）、`USER`（用户）、`ORDER`（订单）
2. 举报状态：`PENDING`（待处理）、`PROCESSING`（处理中）、`APPROVED`（举报成立）、`REJECTED`（已驳回）、`CLOSED`（已关闭）
3. 同一用户对同一目标只能有一个待处理的举报
4. 举报可以附带多张凭证图片

## 9. 前端错误处理建议

- `401`：清理登录态并跳转登录页。
- `403`：展示权限或账号状态提示，不要重试。
- `400`：展示业务错误提示，如参数错误、重复举报等。
- `404`：举报记录不存在。
- `500`：展示系统异常提示，并记录接口与请求参数方便排查。
