# 订单模块开发说明

## 1. 模块概述

订单模块负责处理二手交易的核心交易流程，包括订单创建、卖家确认、订单取消、订单完成等操作，以及订单状态流转和并发控制。

## 2. 开发思路

### 2.1 订单状态流转设计

```
PENDING_CONFIRM（待确认）
    ├── 卖家确认 → WAIT_MEET（待见面）
    ├── 买家/卖家取消 → CANCELED（已取消）
    └── 超时未确认 → CANCELED（系统自动取消）

WAIT_MEET（待见面）
    ├── 卖家完成 → COMPLETED（已完成）
    ├── 买家/卖家取消 → CANCELED（已取消）
    └── 管理员异常关闭 → EXCEPTION_CLOSED（异常关闭）
```

### 2.2 事务处理

- 创建订单：锁定商品（`ON_SALE` → `LOCKED`）+ 创建订单，同一事务
- 取消订单：恢复商品（`LOCKED` → `ON_SALE`）+ 订单置为 `CANCELED`，同一事务
- 完成订单：商品置为 `SOLD` + 订单置为 `COMPLETED`，同一事务

### 2.3 并发控制

- 通过数据库条件更新实现：
  ```sql
  UPDATE products SET status = 'LOCKED' WHERE id = ? AND status = 'ON_SALE'
  ```
- 如果 `RowsAffected = 0`，说明商品已被其他订单锁定，返回错误

### 2.4 超时自动取消

- 订单创建后 24 小时内卖家未确认，系统自动取消
- 使用定时任务每分钟检查一次：`expire_time < NOW()`
- 只有成功更新到订单的执行者才会解锁商品和发送消息，避免并发重复处理

## 3. 接口清单

### 用户端

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/orders` | 创建订单 | 登录+认证 |
| GET | `/orders` | 我的订单列表 | 登录 |
| GET | `/orders/:id` | 订单详情 | 登录（买卖双方）|
| POST | `/orders/:id/confirm` | 卖家确认订单 | 登录+认证（卖家）|
| POST | `/orders/:id/cancel` | 取消订单 | 登录+认证（买卖双方）|
| POST | `/orders/:id/complete` | 完成订单 | 登录+认证（卖家）|

### 管理员端

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| PUT | `/admin/orders/:id/status` | 管理员修改订单状态 | 登录+管理员 |
| POST | `/admin/orders/:id/exception-close` | 管理员异常关闭订单 | 登录+管理员 |

## 4. 测试情况

- 创建、确认、完成状态流转测试通过
- 订单列表、详情查询测试通过
- 权限校验（买卖双方）测试通过

## 5. 注意事项

- 订单详情接口严格校验买卖双方身份，防止越权访问
- 管理员修改状态接口不允许直接修改为 `EXCEPTION_CLOSED`
- 定时任务需确保集群环境下不会重复执行
